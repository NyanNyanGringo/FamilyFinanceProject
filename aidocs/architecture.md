# Текущая архитектура

## Обзор
FamilyFinanceProject — монолитное приложение Telegram-бота, которое обрабатывает голосовые сообщения и ведёт финансовые операции в Google Sheets. Архитектура в основном процедурная: прямые вызовы функций и плотная связность компонентов.

## Потоки системы

### 1. Точка входа
- `run_server.py` инициализирует окружение и запускает сервер
- `server.py` содержит всю бизнес-логику в одном модуле
- Команды бота регистрируются для автодополнения в Telegram

### 2. Поток обработки сообщений

```
Голосовое сообщение пользователя -> Telegram Bot -> Voice Handler -> Audio Processing -> OpenAI -> Google Sheets (автосохранение)
```

### 3. Поток обработки команд

```
Команда пользователя -> обработчик команды -> Google Sheets -> Отформатированный ответ
```

#### Обработка текстовых сообщений (Memory)
```
Текст пользователя (#префикс) -> Telegram Bot -> Memory Text Handler -> Google Sheets (#memory)
```

#### Подробные шаги
1. **Получение голосового сообщения** (`voice_message_handler`)
   - Получает голосовое сообщение из Telegram
   - Скачивает и конвертирует аудиофайл (OGA -> WAV)

2. **Преобразование аудио в текст**
   - Использует Whisper (OpenAI) или Vosk для распознавания речи
   - Настраивается через класс `Audio2TextModels`

3. **Определение типа операции**
   - Первый вызов OpenAI API, чтобы определить тип операции
   - Проверяет, релевантен ли запрос
   - При необходимости разбивает сообщение на несколько операций

4. **Извлечение данных**
   - Второй вызов OpenAI API, чтобы извлечь структурированные данные
   - Использует отдельные форматы ответов для каждого типа операции

5. **Валидация данных** (`clarify_request_message`)
   - Валидирует категории, счета и статусы
   - Помечает некорректные поля текстом валидации

6. **Автосохранение в Google Sheets**
   - Сейчас голосовые сообщения автосохраняются сразу после валидации
   - Telegram message ID сохраняется в столбцах L, M, K для трекинга
   - Создаёт объект `RequestData` на основе типа операции
   - Выполняет batch update в Google Sheets

7. **Удаление пользователем**
   - Отправляет отформатированное сообщение с кнопкой Delete
   - Кнопка Delete показывает запрос подтверждения
   - Второе нажатие подтверждает удаление строки из Google Sheets
   - Использует `telegram_message_id`, чтобы найти и удалить строку

## Ключевые компоненты

### `server.py`
- **Главный модуль**: содержит всю бизнес-логику
- **Функции**:
  - `voice_message_handler`: основная точка входа для голосовых сообщений (с автосохранением)
  - `button_click_handler`: роутер для callback'ов кнопок
  - `memory_button_handler`: операции кнопок, связанные с memories
  - `operation_button_handler`: операции кнопок, связанные с финансовыми операциями
  - `memory_text_handler`: обработка текстовых сообщений, начинающихся с `"#"`
  - `memory_command_handler`: обработчик команды `/memory`
  - `expenses_status_handler`: обработчик команды `/expenses_status`
  - `clarify_request_message`: валидация извлечённых данных
  - `format_json_to_telegram_text`: форматирование ответов
  - `set_bot_commands`: регистрация команд для автодополнения
  - различные вспомогательные функции

- **Обработчики команд**:
  - `/expenses_status`: помесячная разбивка расходов по категориям
  - `/memory`: управление сохранёнными instructions (memories)

### Утилиты (`lib/utilities/`)
- **`openai_utilities.py`**: интеграция с OpenAI API
  - Преобразование текста в текст
  - Преобразование аудио в текст
  - определения форматов ответа
  - сборка запросов
  - `_get_memory_context()`: добавляет memories во все API-вызовы

- **`google_utilities.py`**: интеграция с Google Sheets
  - аутентификация
  - пакетные обновления (batch updates)
  - enum'ы для категорий, операций и т. п.
  - `delete_row_by_telegram_id`: удаляет строки по Telegram message ID
  - ссылки на столбцы: расходы (AK), доходы (AL)
  - функции памяти: `get_memories()`, `add_memory()`, `delete_memory()`
  - enum `ListName` содержит названия всех вкладок

- **`telegram_utilities.py`**: Telegram-специфичные функции
- **`ffmpeg_utilities.py`**: конвертация аудио
- **`vosk_utilities.py`**: альтернативное распознавание речи

## Модели данных

### Типы операций
- Расходы (`OperationTypes.expenses`) -> вкладка `↙️Расходы`
- Доходы (`OperationTypes.incomes`) -> вкладка `↗️Доходы`
- Переводы (`OperationTypes.transfers`) -> вкладка `🔄Переводы`
- Корректировка (`OperationTypes.adjustment`) -> вкладка `🔄Переводы` (как один из типов перевода)

### Ключевые классы/enum'ы
- `OperationTypes`: enum типов операций
- `Category`: управление категориями расходов/доходов и счетами
- `Status`: статусы операций (`Committed`/`Planned`)
- `RequestData`: модель данных для обновлений Google Sheets

## Проблемы текущей архитектуры

1. **Монолит**
   - Вся логика в одном файле `server.py`
   - Сложно тестировать компоненты по отдельности
   - Тяжело поддерживать и расширять

2. **Плотная связность**
   - Прямые зависимости между компонентами
   - Нет чёткого разделения ответственности
   - Бизнес-логика смешана с инфраструктурой

3. **Ограниченная масштабируемость**
   - Нельзя обрабатывать операции независимо
   - Нет модульности для добавления новых возможностей
   - Только последовательная обработка

4. **Обработка ошибок**
   - Базовая обработка ошибок
   - Сложно восстановиться после частичных падений
   - Ограниченное логирование и мониторинг

5. **Дублирование кода**
   - Похожие фрагменты логики повторяются для разных типов операций
   - Нет переиспользуемых компонентов
   - Захардкоженное форматирование ответов

6. **Сложности с тестами**
   - Тяжело писать unit-тесты
   - Зависимости от внешних сервисов
   - Нет mock-интерфейсов

## Зависимости
- Python 3.10
- telegram (`python-telegram-bot`)
- OpenAI API
- Google Sheets API
- ffmpeg (системная зависимость)
- Vosk (опционально)

## Конфигурация
- переменные окружения в файле `.env`
- Google-креды в папке `google_credentials`
- модели Vosk в папке `models` (опционально)
- Docker volume для сохранности `voice_messages`

## Недавние изменения

### Автосохранение голосовых сообщений (июль 2025)
- Все валидные голосовые сообщения автоматически сохраняются в Google Sheets
- Telegram message ID сохраняется в столбцах L, M, K
- Удаление в два шага с подтверждением
- Кнопки Accept/Decline заменены на одну кнопку Delete

### Система команд (август 2025)
- Добавлена команда `/expenses_status` для ежемесячного трекинга расходов
- Включено автодополнение команд в Telegram
- Команды читают данные из отдельных вкладок Google Sheets

### Улучшения инфраструктуры
- Исправлено кэширование установки Poetry в Docker
- Директория `voice_messages` вынесена в Docker volume
- Улучшена обработка ошибок прав доступа

### Система памяти (август 2025)
- Добавлен обработчик текстовых сообщений, начинающихся с `"#"`
- Реализована команда `/memory` для управления сохранёнными инструкциями
- Memories хранятся во вкладке `#memory`, ячейка A1
- Memories используются как приоритетный контекст для всех вызовов OpenAI API
- Двустороннее взаимодействие: сохранить через `#`, управлять через `/memory`

### Рефакторинг (август 2025)
- `button_click_handler` разделён на три специализированных обработчика:
  - `button_click_handler`: главный роутер
  - `memory_button_handler`: операции памяти
  - `operation_button_handler`: финансовые операции
- Захардкоженные названия вкладок перенесены в enum `ListName`
- Улучшена организация кода в духе Single Responsibility Principle
